# 实战案例：Next.js 16 + OpenNext + D1（单区域 WNAM）游戏站，2026-10

> 栈名词与"为何边缘也慢"见 background.md；步骤细节见 playbook.md；其它平台映射见 other-stacks.md。下列数字来自约 42 地点 × 3 轮 Globalping，热窗口约 T+10min。

技术栈：Workers + Static Assets，D1 在美西，游戏页和结果页是动态页，另有 17 个纯静态的 SEO 页。用 Globalping 在 42 个地点各跑 3 轮。

## 基线诊断
- 建连只占 15–60 ms，80–95% 的时间都是服务器端耗时。
- 首页：每次请求都做 SSR，`s-maxage` 没有生效，冷启动要加载 7.3 MB 的 handler。热的时候 50–150 ms，冷的时候 0.5–1.5 s。
- 结果页和分享页：要串行查 4 次 D1，分享页还因为 metadata 和页面各查一次而重复查询。非本人打开结果页会先 307 到分享页，再查一遍。北美以外要 1.8–2.5 s。
- Smart Placement 开着，但所有请求都是 `local-*`，等于没有生效。

## 经验
- 收益最大的三步是 B、C、D。E 收益很小。CF-1 主要是去掉误导性配置。
- 打开 Smart Placement 做 A/B：北美变快，全球变慢 → 保持关闭。另外它不随版本回滚。
- Early Hints 没有效果，因为响应里没有 Link 头。
- 北美偶尔约 350 ms，原因是冷实例：回滚到旧版本也一样，不是代码回归。
- 3 次 E2E 都出现过同一个 2 px 偏差的 UI flake，单独重跑都能通过，已在报告里单独列出，没有掩盖。
