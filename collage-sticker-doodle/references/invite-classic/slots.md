# 素材槽位与约束（PART 1）

> v5：先读 SKILL.md 顶部的 P0 表。素材约束都是为了让 P0 能在不缩得太小的情况下满足。

## v5 新增槽位和预检
| 槽位 | 说明 |
|---|---|
| `Sx.landscape_subject` | 建筑/地标主体框，**源图**归一化 `{"u","v","w","h"}`。渲染器自动选最小缩放（1–1.7）让它居中且完整落在照片片内；QA 用它算遮挡比例。缺了会用默认框并 WARN |
| `Sx.landscape_mask` | v6 可选：强制遮罩类型 skyline/torn/arch/circle/heart/blob |
| `Sx.landscape_ground` | 照片片（v6：W+80 × H−290 的近满版裁切）里地面线的高度比例（0.85–0.97），人物脚放在这里（街道、沙滩、草地、甬道地面） |
| `S1.prop_tv_screen` | `tv_screen.py` 输出的 json（玻璃屏 bbox、四边形、圆角半径）。必须是真实复古电视照片的抠图 |
| 道具 | **每场景最多 1 个**（留白规则）；多给的 validate 会 WARN 并只用第一个 |

**风景预检（approved #5，`landscape_check`）**：优先远景 / 有纵深的照片（天际线、长街、海岸线、甬道）。WARN 条件：画幅 <1.3；没有地平线（行亮度梯度 <0.02）且上 1/3 没有天空/远景带；细节密度 <0.06（放大的近景局部或虚焦）。这是启发式：在本测试集上 5 张全景都过，5 张中心裁切近景有 4 张被拦下。


bbox 写成 `[x, y, w, h]`，都是画面宽、高的比例，参考帧是原片 720×998。**比例值在 720×998 和 1080×1920 下通用**；换到 1080×1920 时乘 1080/1920 就是像素，例如 [0.30,0.60,0.50,0.40] → x324 y1152 w540 h768。由于 1080×1920 更高，人物 bbox 以**底边对齐**为准，顶部多出来的空间留给色块和文字。
- 人物 bbox 来源：白边贴纸的连通域【实测】（白边 mask 会把白婚纱一起算进去，所以偏大，误差约 ±0.03）。
- 文字和道具的 bbox：看帧量【估】。
- 默认【可调】容差：中心 ±10% W/H，缩放 0.8–1.2 倍。下表另有写明的以下表为准。

## 全局照片规则
| 规则 | 级别 |
|---|---|
| A/B 两张照片**同一场景、同一组拍摄、同服装**，两人位置要明显不同（换站位、一前一后、拉远）；渲染时还会把 A/B 放到不同位置 | 【硬锁定】 |
| 人物照在抠图时统一调成胶片暖调（黑白照着色），不用事先统一色调 | 【v4】 |
| 同一场景人物脚底线对齐（差 ≤1% H）；画面底边可以裁掉脚踝以下，但 A/B 要裁在同一条线上 | 【硬锁定】 |
| 人物顶部留头顶空间 ≥3% H，不要让头碰到上面的文字带 | 【硬锁定】 |
| 背景简单（纯墙、天空、草地），主体和背景对比明显，没有大面积头发、婚纱和背景融在一起 | 【硬锁定】（不满足就警告） |
| 最低分辨率：人物原图长边 ≥1500px；景观图短边 ≥1080px | 【硬锁定】 |
| 色调偏暖、偏低对比；过曝（婚纱死白 >5% 面积）会警告 | 【可调】 |
| 全部是双人照；S2、S9 允许情侣贴靠的单张合影 | 【可调】 |

## 姿势舒展度预检【v4】（validate_manifest.py → `spread_check`）
情侣紧贴成一团的照片，抠出来就是一坨，跳动和 A/B 都显得没动。用 cutout.py 输出的 `cut/*.mask.png` 量：
| 指标 | 算法 | REJECT | WARN |
|---|---|---|---|
| spread | 人物 mask 外接框宽 / 高 | <0.45，且只有 1 个连通域、内部无空隙 | <0.6，且内部竖向空隙 <5% 宽 |
| 太宽 | 同上 | — | >1.15（按宽度限制后人物会低于 50% 画面高） |
优先选这些姿势：拉远牵手、一前一后、走开回头、伸手够对方、一坐一站。不要选：紧贴拥抱、贴脸自拍、两人叠成一个轮廓。

## A/B 预检【v4】（`ab_check`）
| 指标 | 算法 | REJECT | WARN |
|---|---|---|---|
| bg_sim | 两张图在"两人都不在"的背景区域，灰度去均值去方差后的相关系数（96×128） | <0.25（不像同一机位 / 场景） | <0.45 |
| iou | 两张人物 mask 的 IoU | >0.88（姿势几乎一样） | <0.15（人跳得太远） |
| pose_diff | 人物区域内平均灰度差 | <10 | — |
注意：暗光、人多的婚宴现场，bg_sim 会偏低（0.2–0.35）；真是同一组照片就接受 WARN。纯色暗背景会让 bg_sim 偏高，不能单靠它，要人工看一眼是不是同一套衣服、同一个地方。

## BGM 规则
- 时长 ≥38.43s；更长的就从最响的副歌前一小节开始截，尾部 1s 淡出【可调】。
- 测 BPM：T = 一个八分音符对应的帧数；如果 T 在 10.5–13.5 帧之外，改用四分音符或十六分音符，直到落进这个范围。
- **默认不改 T**：T 与 12.25 差 ≤0.4 帧时直接用 12.25，让音乐对齐第一个强拍（偏移 BGM，不动画面）。
- 差距更大时：按 timeline.md 的公式整体伸缩，片长 = 38.43·T'/12.25，**场景顺序和步数不变**【硬锁定】。
- 歌词人声开始的位置最好落在 S4 附近（8–9s）【可调】。

## 命名约定
`assets/S{n}_{slot}.{jpg|png}`，A/B 用 `S5_A.jpg` / `S5_B.jpg`；抠好的图输出到 `cut/S5_A.png`；BGM 是 `assets/bgm.mp3`。

## manifest.json schema（简版）
```json
{"template":"string","output":{"width":1080,"height":1920,"fps":30},
 "bgm":{"file":"path","bpm":"number|null","offset_sec":"number"},
 "names":{"groom":"str","bride":"str","groom_tag":"str","bride_tag":"str"},
 "scenes":[{"id":"S1..S10","slots":{"<slot_id>":"path | text | builtin:<name> | [list]"}}]}
```
完整示例见 `../assets/manifest.example.json`。

## 校验（自动脚本思路）
| 检查 | 方法 | 拒绝 | 警告 |
|---|---|---|---|
| 分辨率 | PIL 读尺寸 | 人物长边 <1000 | <1500 |
| 抠图质量 | rembg alpha：0<α<255 的半透明像素占比；连通域数量 | 主体连通域 >2 或 alpha 面积 <8% | 半透明边 >6%（头发糊、婚纱发灰） |
| A/B 相似度 | 背景区域 SSIM ≥0.6（同机位）；人物 mask IoU 在 0.2–0.85（是真的换了姿势） | 背景 SSIM <0.4 | IoU >0.85（几乎一样）或 <0.2 |
| 脚底线 | mask 最低行，A/B 差 ≤3% H | — | >1% |
| 文字长度 | 按上表每行字符数 | 超出 50% | 超出 |
| 字形 | 渲染前 `assertGlyphs` | 缺字 | — |
| BGM | 时长、librosa BPM | <30s | <38.43s 或 T 超出范围 |
| 必要槽位 | S5–S7 的 A/B、名字、日期、地点 | 缺名字、日期 | 缺 A/B（降级成单姿势） |

## v7：人物完整性（P0-6）
- `Sx.people_count`（默认 2）：该场景照片里应完整出现的人数，cutout.py `--expect` 与 run.py `--person-check` 都用它。
- 人物照约束新增：两个人都要完整入画（至少到大腿，身体只能被**底边**裁）；不要选一人被另一人大面积挡住的照片（抠图常把被挡的人切成头+手臂）；不要选人在原图左/右/上边被裁的照片。
- 半身照（腰部被原图底边裁）只能放在贴纸底边贴着画面底边的位置，否则成片里会出现一条悬空的直线切口——P0-6 会给出"关键点在源照片外"警告，必须在拼图里确认。
- 依赖：`pip install mediapipe`，模型 `pose_landmarker_full.task`（https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_full/float16/latest/pose_landmarker_full.task，放到 /workspace/models/ 或设 POSE_MODEL）；Linux 需 libegl1。
