# R2 媒体完整验收矩阵

实施规则以 [R2](r2.md) 为唯一来源；此文件只定义输入、期望及证据层。使用隔离数据和项目已安装runtime，不在生产试读其他人的私有对象、撤下真实内容或清缓存。

| 输入/状态                          | 期望                                                          | 证据                    |
| ---------------------------------- | ------------------------------------------------------------- | ----------------------- |
| 普通冷GET                          | 0 head + 1 get，完整字节和正确MIME/长度                       | 调用mock + workerd/R2   |
| 初次合法单段Range                  | 大小未知可0 head + 1 get，仅该段                              | 真实R2元数据/字节       |
| 重复同段                           | 缓存可用且回填后HIT，0 R2，摘要一致                           | workerd Cache API       |
| 完整缓存后其他Range                | 0 R2，平台截段状态/头/字节正确                                | workerd而非fake自行切片 |
| 不同段首次读取                     | 仅该段get；后台工作完成后也无整片get                          | 前后调用计数            |
| 冷/热HEAD、304、412、416           | 正确前置条件、缓存/校验头、无body及调用次数                   | 冷热各测                |
| start-end/open/suffix、EOF截尾     | 规范化段与实际长度/正文一致                                   | 纯解析 + runtime        |
| 零字节、suffix=0、倒序、非法、多段 | 按明示协议忽略/416等，冷/热一致                               | 边界回归                |
| 超安全整数Range                    | 统一解析，不错标206、不污染full/range键                       | 真R2 + 后续正常请求     |
| If-Range强/弱/旧/无效/未来日期     | 强ETag或可用日期精确相等才分段，否则完整200                   | 冷/热及已缓存full       |
| 条件头组合、星号/多值/弱ETag       | If-Match和If-None-Match优先级正确                             | 解析 + runtime          |
| 应用SHA与存储ETag不同              | 应用条件正确，不传错误onlyIf                                  | 调用参数 + runtime      |
| onlyIf无body与缺对象null           | 分别判断304/412与缺失，不混淆                                 | 真R2                    |
| 匿名/其他用户或租户访问热对象      | 资格拒绝，HEAD/旧ETag/Range均无泄漏                           | 业务路由/隔离数据       |
| 公开对象热后下架/换版本            | 当前资格优先；旧地址不得靠304泄漏                             | 隔离数据及旧URL/ETag    |
| 草稿/敏感/可变对象                 | 外部no-store和内部bypass同时生效                              | 头 + 调用数             |
| 同key跨桶/租户、不同下载名         | 字节不碰撞，下载名逐请求重建                                  | namespace/响应检查      |
| 元数据或字节各自淘汰               | 正确恢复，缺项不假装HIT                                       | 可注入cache             |
| 超预算完整/段响应                  | 正常流式交付，无超预算复制/回填                               | 分支/调用数             |
| cache.match/put/defer失败          | 主结果不变，无未处理Promise，失败计数可见                     | 注入故障                |
| 缺对象、坏元数据、真实R2异常       | 按项目错误合同处理，无错误回填/悬挂流                         | 错误回归                |
| 公开/私有浏览器缓存                | 网络授权仍前置；本地撤权窗口按已批准策略                      | 配置 + 浏览器记录       |
| CDN/代理/Service Worker规则        | 不能覆盖资格边界或透明改字节                                  | 实际规则 + 拒绝请求     |
| 封面、首播、拖动、音频/下载        | 图片naturalWidth、视频时长/readyState有效，可解码且seek后继续 | 真浏览器                |

用项目版本的 Miniflare/workerd、R2 binding、Cache API打包共用核心，runtime中包装bucket计数；构造器/schema以安装版本为准。cache store、defer可注入，真实自动Range必须在workerd测。waitUntil异步回填用有界轮询观察HIT；记录淘汰/未命中，不用固定sleep证明必命中。

只读测量统一走 [测量](measurement.md) 的probe；状态/段长/SHA一致仅证明此次传输合同，不证明权限、真实存储次数或解码。没有内部诊断头就留空，304不算正文缓存HIT；浏览器缓存的旧HIT头也不证明本次访问Worker。

完成条件：每行标明通过/失败/跳过/不适用及原因，冷/热分别有证据；已实现、功能正确、实测加速三种结论独立记录在 [执行模板](../assets/performance-report.md)。
