# 实战证据与移植边界

本页用于判断哪些模式有执行依据，以及哪些结论仍未验证。日期为 2026-11-07 整理。案例站点的产品名、域名、仓库路径、提交、账户、凭据、私有链接和原始会话均不随包分发；下文按职责描述模块，在接收项目中自行定位对应位置。

## 已做的优化

实战站点是一个 AI 视频制作平台，采用 TanStack Start / React / Vite / Drizzle、Workers、D1、私有 R2、队列和后台渲染容器。已实施的模式包括：

- 网络：对比主域与区域同源代理入口，检查 DNS/握手/重定向；保持登录、业务 fetch、OAuth 回跳和 SSE 的 origin 合同。
- D1：模块级 ORM 经请求级会话路由；展示从无约束/书签位置读取，认证与机器请求保留主库；客户端统一 fetch、跨标签页合并、SSR 和 SSE 传书签。
- R2：普通 GET 减少固定 head→get；鉴权与不可变字节分层；完整/分段独立 Cache API 键，条件请求、If-Range 和实际字节一致性检查。
- Worker/HTML：公开页面内部缓存、构建版本键、后台刷新；SSR 与静态资源分别设置响应头，避免误把 `_headers` 当 SSR 配置。
- 前端：UI 字体自托管并保留许可、关键资源与模块加载调整、客户端共享查询/失效、骨架与播放器/预览加载整理。
- 发布：最新合并后重跑检查，从干净已推送提交构建/发布，核对 Worker 实际版本与任务/沙箱，再用已有用户身份只读验证。

这些动作不是所有接收项目都要实施的清单；按其瓶颈和产品合同选择，通用实施细节以各分支文件为准。

## D1：功能验证，不虚构加速比例

统一会话涉及的模块（按职责描述）：

- 深层数据库入口：请求会话、权威主库。
- 客户端书签模块：书签传递与跨标签页合并。
- Worker 入口与 ServerFn 中间件：每个请求建立会话。
- 流式回复接口：流式事件中传递书签。
- 单元测试与真实 workerd 端到端测试：并发、模块级 ORM 合同。

已验证本地真实 runtime、书签迟到/多标签页与业务测试；收尾全量单元测试通过（少量既有跳过项单列），默认端到端 50 项、书签相关专项端到端 31 项通过。正式版本上线后，已有用户的 API 与真实 ServerFn 请求成功带出/回传书签，未创建生产测试数据。

**未测得**受控 D1 前后性能 A/B、真实 APAC 副本命中与可靠 P95 收益。上述结果证明实现/集成/部署完成，不证明页面已快某个百分比。下一步需要远程 binding meta 和同条件基线。

移植时已纠正一处事实边界：官方 Time Travel 明确书签可按字典序从旧到新排序；通用实现用确定性的字符串顺序，不解析内部格式，且同数据库、跨标签页合并必须原子化。不要因为历史项目使用过某种比较函数就复制其区域排序语义。

## R2：同版本冷热收益，不是前后 A/B

历史媒体缓存优化分两步：公开媒体缓存的 If-Range 检查及验收；共用不可变字节缓存、减少重复 R2 读取。涉及公开内容媒体路由、统一媒体响应模块及其真实 runtime 测试；在接收项目中按职责定位对应模块，而不是安装依赖。

已有低量实测：同一版本、同一公开视频的 64 KiB 分段，MISS 首响应约 **473 ms**，HIT 约 **185 / 194 ms**，热命中较该次冷请求下降约 **59–61%**。该测量由媒体优化线程记录；它不是 D1 收益，也不是严格的旧版→新版对照，更不保证所有地区/整片下载同样快。

调用计数与字节验收支持普通冷 GET 可为 0 head + 1 get、已命中片段可无 R2 读取；必要冷 HEAD/越界/If-Range 元数据仍允许 head。必须用实际计数与摘要验证，不能从代码分支数量推断调用数。

缓存 TTL、整片/片段阈值和浏览器私有缓存时长是该站点历史策略。通用私有媒体默认按敏感性与撤权要求选择 no-store/每次验证；不能把私有缓存 1 天推广成安全默认。

私有同片同64 KiB段另有一个冷MISS约3213 ms，7个HIT为1130、736、538、389、802、1325、353 ms，中位736 ms。发布前同段约1秒但服务机房前后不同，不能据此归因前后收益。小样本不是可靠P95、并发或整片播放报告，权限/网络仍包含在首响应内。

## 前端与HTML：历史功能观察

- UI移除首页Google Fonts CSS；等宽latin WOFF2 400/500约21/22 KiB并保留OFL，中文系统回退。首屏Google字体请求为0、等宽/中文正常；未做字体耗时或LCP受控A/B，不涉及产品内编辑器或渲染自身的字体替换。
- 公开HTML同版本样本：等待400秒后STALE约334.715 ms，随后HIT约284.693/181.679 ms，支持旧副本即时返回/后台刷新功能，不证明新部署build键无首个MISS。
- 纯语言根路径（如 `/xx` → `/xx/`）在SSR前308并有限缓存、保留query，地区/用户偏好规则未改。
- 同批主入口HIT仍约1.27–1.74秒、地区入口约0.15–0.23秒，说明应用缓存未消除入口绕行；线路会漂移，不当作所有地区保证。
- 浏览器复访55/11 ms且transferSize=0，无受控修前值；结合浏览器记录为缓存观察，不单凭0证明无网络。既有10秒视频可播无media错误，中文首屏图片未损坏。
- 前端优化阶段曾有服务未启动ECONNREFUSED、高负载和渲染超时，不能写成该阶段全套全绿；与后续D1收尾数字不是同一轮。

## 不照抄历史实现的边界

已有实现并不自动等于通用安全合同，本 SOP 提高了以下验收要求：

- HTML：逐一审计公开路由、所有身份 Cookie/Authorization、private/no-store、Set-Cookie、Vary、Host/语言/模式/query；不能只检查某个登录 Cookie 或固定域名。
- HTTP：Range 只用于 GET，HEAD 忽略 Range；旧 helper 的 HEAD+Range 206 不作为规范推荐。冷/热 304/412/416 的头、前置条件顺序与巨大整数范围统一。
- D1：提交的 first-primary 只保证首查，认证仍需权威入口；会话不取代 CAS/幂等、身份缓存撤销或 UI 数据 revision 合并。
- 字体：UI 的 WOFF2 自托管不证明整个视频渲染依赖已无 Google Fonts。分别审计浏览器 UI 与视频渲染环境。
- 缓存：外部 no-store 不自动关闭内部 Cache API；cache.delete 仅本 POP，不代表平台绝无全球 purge；自定义内部键需验证对应的 purge 方法。
- 区域代理：项目已有入口不代表接收项目获得 VPS/费用/DNS 发布授权；可信转发头需要来源验证，普通内容压缩应保留。

完成条件：接收项目报告自己的证据和限制；本页数字只能标为历史案例，不能填进新项目性能验收表。
