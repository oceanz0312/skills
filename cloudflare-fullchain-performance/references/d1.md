## 盘点与基线

读取项目Agent/部署规范、包管理器、安装ORM/CLI版本、配置源与generated types。列出D1绑定、主库地区、jurisdiction、`read_replication.mode`和所有ORM/raw/auth/后台入口，确认本地是否绑定生产资源。

- 普通 `env.DB` 查询默认主库；开启副本不会自动改旧查询，须用binding Sessions API。REST不支持Sessions，不能验证副本路由。
- 官方当前说明副本存储/计算不额外收费，仍按rows_read/rows_written计费；部署时重查价格和计划。启用副本是D1设置写操作，取得对应批准/scope。
- mode为auto才启用副本。地区由平台部署，不创建“香港读库”绑定；jurisdiction限制副本，不承诺每库都有全球副本。
- 从同地区、入口、身份与数据采样：每操作查询数、batch数、rows_read、SQL执行与端到端耗时。没有基线就不填写收益百分比。

完成条件：每个入口有用途和一致性分类；主库/副本设置有实查依据；清楚区分网络慢、扫描慢、串行往返和前端重复请求。详见 [验收与测量](d1-verification.md)。

## 选择路由合同

| 场景                                        | 读取起点                               | 边界                                           |
| ------------------------------------------- | -------------------------------------- | ---------------------------------------------- |
| 展示，可短暂落后于别的设备，无历史位置      | `withSession('first-unconstrained')`   | 首查可以主库或副本，不强制最近地区             |
| 展示，不早于本浏览器已确认位置              | `withSession(bookmark)`                | 至少追到位置，不等于全局最新                   |
| 用户提交，需最新起始状态                    | `withSession('first-primary')`         | 仅首查主库，后续不早于它，不保证每条SELECT主库 |
| auth/角色封禁撤销/关键资金库存/即时下架资格 | 独立权威主库入口 + 条件写/原子业务规则 | 主库也不消除检查后变化的竞态                   |
| Webhook/任务回调/queue/cron/请求外服务      | 默认主库；有产品合同才另选             | 不继承浏览器展示状态                           |

同会话的写发主库，后续读可看见写入，平台保证顺序一致性。会话不是事务/锁/幂等；保留CAS、唯一约束、原子余额/库存更新，不能把SELECT后UPDATE当自动安全。

副本等待书签没有此SOP可承诺的固定上限/自动主库回退；“通常同步500ms内”不是SLA。美国用户也不能保证改用副本性能绝无变化，是否同地区primary须实测。

完成条件：按业务用途选择，不能仅按GET/POST或客户端自报“只读”分类；展示延迟与提交正确性分开。

## 统一请求级入口

按 [完整实施顺序](d1-implementation.md) 改造中央入口，而不是为每个页面选择读库函数：

1. 优先显式request context；模块级ORM普遍存在时用Workers支持的AsyncLocalStorage.run。核对compatibility_date/nodejs_compat和真实runtime。
2. `prepare`/`batch`执行前查当前请求会话，模块级ORM不捕获首次请求。prepared statements不可提前跨请求创建并复用。
3. 每binding一套路由器。认证适配器独立主库；机器/队列/cron默认主库。waitUntil可能继承ALS，权威后台显式清除会话。
4. 业务写通过同session执行，避免绕过入口写入后当前书签未覆盖它。管理/迁移接口走请求外批准工具，不悄悄绕主库伪装成会话写。
5. 按项目兼容政策替换旧入口；保留CSRF/auth/业务事务，测试所有调用者，更新接收项目现状文档。

可移植代码在 `assets/d1-request-database.ts`：显式policy、模块级Drizzle、当前会话与独立权威实例。它是需接入本项目schema/handler的模板，不是自动覆盖代码的脚本。

完成条件：SSR、ServerFn、API、流式工具和后台调用全部有路由依据；本地真实workerd及类型检查通过，不以Node mock替代。

## 跨请求书签与并发

书签是数据库位置，不是认证权限；内部格式不解析。响应可用应用自定义header，客户端在交给业务前保存，下次同源header/SSR cookie继续位置。

- 校验体积、可见字符和保留约束，cookie编码；非法/不可用位置按有界恢复合同处理，提交不依赖非可信cookie。
- cookie按数据库命名空间、host-only、SameSite、HTTPS Secure设置。寿命是产品策略，不把Time Travel恢复窗口当Sessions过期合同；不同库/重建库不混位置。
- 官方Time Travel明确书签可字典序从旧到新排序，取同数据库最大位置；用确定性字符串比较，不用localeCompare的区域排序/猜hex数字。
- Web Lock在同源多标签页原子合并“读→比较→写”，不能让慢response Set-Cookie刷回旧值；无锁/禁用cookie显式选择服务器托管、真实串行方案或限定单标签页保证。
- 统一客户端fetch覆盖ServerFn公共fetch和直接API，保留Request/init/signal语义。第三方上传不携带/采纳位置；公开HTML/CDN响应不带个人书签或Set-Cookie。
- SSE发头之后继续写时，在后续业务事件前发db_bookmark事件；客户端await合并后刷新，保留断连/取消/重复提交合同。
- 位置不会自动避免UI旧revision响应覆盖，也不包含其他设备/未收到的后台写入，分别处理。

可移植代码在 `assets/d1-browser-bookmarks.ts`，包括shared lock、cookie读回检查与保存失败事件；调用方须显式处理同步缺口，不因已完成写入的存储问题自动重试。

完成条件：实际浏览器ServerFn/API/刷新SSR/SSE/迟到轮询/多标签页/外站请求都经过验证，公开缓存不泄漏位置。具体接入和异常分支见 [实施参考](d1-implementation.md)。

## 减少往返与扫描

根据基线实施，不把每条SQL改副本当全部优化：同响应独立查询batch/并行、消除N+1/重复认证、合并导航统计、正确索引/选择列/分页、SSR预取/统一Query key及写后失效。

真正依赖上一步的操作不盲并行，索引DDL按资源变化批准并验证执行计划/rows_read与写入开销；详见 [查询优化表](d1-implementation.md#查询与客户端缓存优化)。

主库创建location hint为best-effort；jurisdiction和hint不能作为已有库原地迁区命令。优先会话与查询优化，迁库先设计数据一致性、切换/冻结窗口、书签重命名与独立回滚，并取得批准。

完成条件：每项动作有调用数/扫描/耗时证据或明确未量化项，分页、权限、精度、保存后列表/sidebar刷新没有退化。

## 验收发布与交付

按 [D1验收矩阵与发布流程](d1-verification.md) 执行。远程binding的`served_by_region/served_by_primary`才能支持此次副本命中结论，`timings.sql_duration_ms`不含网络，记录聚合/受限诊断，不公开SQL/凭据/完整书签。

遵守接收项目授权和现有发布路径，本地隔离优先；只有批准后才启用副本/变更索引/迁库/上线。代码回滚不还原数据和设置；停用副本最多24小时才停止副本处理，需要即时主库读取时切应用路由并验证。

完成条件：入口清单、正确性矩阵、测试通过/失败/跳过、版本资源变更、同条件收益或未测项齐全。将已实现、已功能验证、已实测加速分开，不把历史其他层缓存收益当D1收益。
