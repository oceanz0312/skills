# 验证、发布与回滚 SOP

此 Skill 是执行方法，不是站点发布授权。遵守接收项目现有分支、审查、任务、兼容和环境规则；没有常设批准时先确认对应生产动作。

## 本地验证

1. 找实际配置源、安装版本、生成步骤、测试目录、构建环境变量。验证本地 binding 的 remote开关，隔离测试数据库和桶；本地 Worker也可能写生产。
2. 手工走查用项目指定浏览器；自动化使用项目已有规格。已有登录身份只读线上，不造生产账号、任务、付款或内容。
3. 非默认测试端口必须让 browser baseURL、构建时URL和Worker runtime vars一致；仅设置 Playwright PORT不能改变邮件登录/支付回跳。
4. 跑影响面的unit、真实workerd/runtime、E2E、typecheck、build，格式化/检查改动文件。请求隔离/Cache API不能只靠Node mock验收。
5. 重型构建、浏览器与渲染按机器能力串行；高负载下减少自己测试并行和媒体/浏览器子进程，延长有界任务上限；超时/失败如实记录，合理定位后复跑。禁止重启别人服务、清共享状态或stash工作树来腾检查环境。
6. 文档冲突按代码更新；测试配置缺项不靠删除断言/改业务掩盖环境问题。通过项、失败项、跳过项、未测项分列。

### 前端与缓存影响面

- 字体：外部请求消失、WOFF2/MIME/许可、实际平台computed font/缺字/位移，按 [前端](frontend.md) 验收。
- 静态：GET正文与HEAD头、真实hash变化、旧HTML/chunk可取、无重复冲突头。
- HTML：匿名/认证、租户/locale/偏好/query/Host、Set-Cookie/Authorization、HEAD无body、并发STALE和失败后再刷新，按 [HTML](worker-html.md) 验收。
- 跳转：GET/HEAD、query保留、POST/循环/地区偏好/canonical，按 [网络](network.md#规范化与地区跳转) 验收。
- 客户端：生产chunk实际懒加载、入口字节/长任务证据、SSR/hydration、登录/导航/权限/提交与写后失效不退化。
- 媒体：执行 [完整矩阵](r2-verification.md)；HTTP状态成功不替代权限/字节/播放正确。

## 发布前检查

- 使用最新目标分支变基/合并并复核影响；多会话/团队约定谁先发布，后者包含前者，不覆盖版本。
- 对账户、Worker、域名、D1/R2/队列/沙箱、配置源/产物进行身份核对，取到所需scope；使用仓库外受保护凭据，不把值放命令参数、代码、日志或Skill。
- 从已推送提交的干净独立worktree发布。核对git status、remote commit及环境生成产物；部署脚本声称clean不等于已检查全部untracked或已推送。
- 查queued/running任务及长SSE/沙箱容器；如果现有发布会重启容器或影响任务则等空闲。遵守既有preflight，不能绕过以赶工。
- 评估schema迁移先后/存储切换/不兼容窗口；数据迁移或收费配置变化单独批准。普通性能优化优先不迁库、不迁桶、不改计费事务。
- 当前线上settings与版本记录和配置对齐，避免Wrangler覆盖dashboard配置。兼容日期升级是另一个需要验收的变更。

## 正式执行

按项目标准命令顺序执行资源预检、已批准迁移、必要后端发布、任务包、正式构建/Worker部署。不要为了本Skill改用绕过保护的单条wrangler deploy。

- VITE等构建变量与runtime配置不同；构建时选择正确production环境，部署env不会重新解释已生成的flattened产物。
- 只有输入真的改变才重建/发布沙箱；若需要Docker基础镜像且仓库不可达，可使用可信官方镜像代理/镜像源，验证digest来源，不能因为网络慢升级不相关依赖。
- 发布成功记录git commit、Worker版本、traffic百分比、资源变更和配置。CLI上传成功不等于全部流量已切换，回读deployments/version。
- 自定义域/正式路由实际检查HTML、API、媒体、SSE/登录边界，cache preview行为不等价于正式命中。确认无新增错误/异常调用量。

## 性能与回滚

发布后使用measurement同条件方法复测，只归因已控制变量的层；网络colo变化要分组，不把R2热命中收益算作D1收益。

- 检查全局/用户权限，热缓存匿名/其他租户不能访问；可撤销内容的浏览器缓存残留窗口告知产品。
- D1查看实际副本meta；没有数据就不能宣称近端副本/具体百分比。业务状态正常才算可交付。
- 回滚Worker不会回滚D1迁移、R2对象/公开设置、DNS、VPS、OAuth或客户端长期缓存。准备相应独立撤销步骤。
- 缓存键build版本化用于部署更新；内容下架/权限变更不能仅靠重部署。回退失效策略先设计，不能随意清空生产桶或数据库。

## 完成条件

只交付文档或本地代码时明确未发布，不为运行本SOP强行部署。若已批准发布，版本须与remote一致且回读流量正确；线上功能/权限与性能结果分别记录；有明确回滚范围；通知受影响协作者接续时给真实commit/version，不把进度消息当完成或用户授权。
