# R2：权限与不可变字节分层缓存

覆盖文件、视频、图片和预览，不把私有桶变公开，也不缓存权限判断。使用 R2 binding，按当前 Cache API 与 HTTP 规范实现。

## 选择交付路径

| 数据合同                          | 路径                                                        | 不能混淆                                          |
| --------------------------------- | ----------------------------------------------------------- | ------------------------------------------------- |
| 永久公开、无需业务逐次撤权        | R2 custom domain + CDN Cache Rules，评估 Smart Tiered Cache | 公开域会绕过应用鉴权；不要暴露混有私有数据的桶    |
| 用户私有、会员权限、可下架案例    | Worker 验证资格 → 内部字节 Cache API → R2 binding           | 即使字节已缓存，每次网络请求仍先过权限判断        |
| 草稿、敏感内容、同 key 会变的对象 | 不缓存，或先做可靠版本化                                    | 只把外部头改 no-store，不会自动关闭内部 Cache API |

生产公开分发使用自定义域而不是 `r2.dev`。R2 桶默认私有；开公开域或关闭访问控制必须单独获得批准。Cache API 每 POP 独立且不使用 Tiered Cache，不能宣传为全球共享存储缓存；需要 Tiered 时用平台支持的公开域/fetch 缓存路径并核对授权边界。

## 减少 R2 往返

普通 GET 优先一次 `bucket.get(key)`，使用返回的 size、httpEtag、uploaded、httpMetadata 与 body，避免固定 `head → get` 串行。

- GET Range 可在大小未知时先向 R2 发合法 range；从结果取得完整对象元数据，正确识别响应分段。
- 冷 HEAD、首次 If-Range、合法越界范围可能需要 head，属于必要元数据读取，不强追“全部零 head”。
- 发布/上传时验证并记录可信完整摘要、总字节数、类型及时间后，在不可变对象的生命周期有保障时，HEAD/304/416 可以只用已验证元数据。它不是独立存在性检查；允许外部删除的对象仍需确认存在，可变对象不能长期复用旧元数据。
- 应用 SHA-256 ETag 与 R2 存储 ETag 不一定相同。已知应用摘要时先在应用处理 HTTP 条件，不把 SHA 作为 R2 `onlyIf` 的存储 ETag。使用存储 ETag 对外输出时用带引号的 `httpEtag`。
- `get` 的 `onlyIf` 条件失败返回 `body` 为 undefined 的 `R2Object`；键不存在才返回 null。不要把无正文的条件结果当成文件缺失。R2 条件头不支持 If-Range，由应用处理。
- 正常缺失/大小不符/读取失败不进入成功缓存，缺对象先修数据路径，不能用缓存掩盖缺失。

## 缓存合同

建立内部键 `站点/租户命名空间 + 桶 + 完整不可变对象 key + 版本 + full 或 offset/length`。若对象 key 已含完整内容摘要，可不再重复版本；namespace 必须避免同 Worker 多租户冲突。

```text
先验证身份与对象资格
  → 按不可变键查元数据/整片/所需分段
  → 命中仍组装当前调用者的响应头
  → 未命中读 R2 并立即返回流
  → 有界分流，waitUntil 保存字节缓存
```

- 缓存只放元数据和字节；对象归属、公开状态、下载文件名不放共享整响应。下载 filename 在返回时按当前请求添加。
- 所有路径（热命中、HEAD、304、Range）先过鉴权。公开资格来自副本时可能有同步延迟；要求即时撤下应权威读取或明确接受延迟。
- 浏览器缓存是另一道产品取舍：敏感/即时撤销默认 `no-store`，或 `private, max-age=0, must-revalidate`。私有 `max-age=86400` 不是通用安全默认；登出/撤权不能召回已有本地副本。
- 需要每次 Worker 资格检查时，外部响应明确 `CDN-Cache-Control: no-store` 和 `Cloudflare-CDN-Cache-Control: no-store`，并检查实际 Cache Rules/代理未覆盖；不要仅凭某个头宣称所有缓存都关闭。
- 内部 `cache.put` 用独立 Response 与内部 TTL，不带 Set-Cookie、认证或访客书签。TTL 来自可接受一致性窗口；不可变字节也可能被逐出，缓存不是持久存储。
- `cache.delete` 只清当前 POP。全局 purge 有独立 API/权限/计划及键限制，不能假定外部 URL 能 purge Worker 自定义内部键；按当前规则验证 tag/host/prefix等方法或用版本键。`Cache-Tag` 在 match响应里不返回，重存需重加。
- 内部命名空间不能被公共 catch-all 直接读取；私有签名 URL 不作可打印缓存标识。内容摘要是版本，不是访问凭证。元数据与字节可各自淘汰，按缺失项恢复；put 成功不保证下一请求 HIT。
- 内部整份/分段大小上限先定预算。有界 stream tee/clone + waitUntil；超过预算只流式返回，不能对大视频 `.arrayBuffer()` 全量驻留。
- 首次 Range 不后台额外下载整片“预热”，避免浪费带宽/内存。缓存写异常捕获后不改变用户响应。
- 键可被覆盖时先版本化，或 no-store；不能将可变同址内容贴一年 immutable。旧 URL 曾长期缓存，改 header 不能召回旧副本，应改变内容 URL 并按项目兼容策略处理。

实战的整份 32 MiB、分段 8 MiB、内部 7 天、公开浏览器 1 小时、私有 1 天都是应用预算和产品策略，**不是 Cloudflare 平台限制/推荐默认**。

## 统一入口与错误

业务路由只负责参数、身份/当前公开资格、对象归属、可信桶/key定位与下载展示；共用响应核心负责元数据、条件/Range、缓存、R2读取和HTTP输出。接口传入 request、bucket、namespace、不可变key、可选可信元数据、外部策略及可注入的 cache store/defer，不把账户模型塞进存储模块。

- 仅缓存成功且符合字节合同的响应；错误、跳转、草稿、坏元数据不回填。版本不符按明确合同返回当前版本地址或404，重定向不入字节缓存。负缓存不是默认优化。
- 缓存读失败降为 MISS；写失败记录脱敏计数，客户端成功结果不变。R2错误不能一概吞为MISS/404：仅映射真实runtime证实的缺对象、条件或越界错误，其余按项目错误流程可观察地处理。
- 冷越界需要补head时，错误码/形态由当前runtime回归确定，不用任意error.message模糊匹配全部异常。
- 拒绝元数据不符、条件失败或无需body时取消上游和未使用流分支。get.size是总大小，返回body可能只有一段；不能用总大小冒充段长度。
- waitUntil按真实execution context托管且有运行上限；后台转码/补预览走任务系统。计数在有界异步工作完成后再次核对，证明没有隐藏整片回源。

## Range 与条件请求

### 完整/分段缓存

- 完整内部对象保存为 200，并带真实 Content-Length；Cache API `match` 可据 Range 返回 206。
- 若只保存分段，在独立 offset/length 键下存 200，删除客户端 Content-Range；对外恢复 206、正确 Content-Range、分段 Content-Length。
- `cache.put` 不接受 206；短段不能存 full 键，分段长度不能充当完整对象大小。
- 验证 Content-Encoding 与字节范围同一表示；代理不透明变换媒体。无法可靠服务 Range 时按规范返回整份而不是伪造 206。

### HTTP 规则

按 HTTP 规范验证方法与前置条件，不照抄已有 helper 的所有行为：

1. 先鉴权，再查可信元数据；条件优先于 Range。
2. If-Match 强比较（弱 ETag 不匹配）；无 If-Match 时才检查 If-Unmodified-Since。没有有效 Last-Modified/非法日期时忽略日期条件，不随意 412。
3. If-None-Match 对 GET/HEAD 弱比较，命中 304；存在它时不再用 If-Modified-Since。条件响应保留所需缓存/校验头。
4. Range 仅对 GET 生效；HEAD 忽略 Range，返回无正文、与完整 GET 一致的元数据。框架必须明确支持 HEAD，helper 有分支不代表路由已注册。
5. If-Range 仅强 ETag 相等或可用的 Last-Modified 日期精确相等才保留范围；未来日期不算匹配。否则忽略 Range，返回完整 200，而不是 412。
6. 支持单段 start-end/open/suffix：终点超过 EOF 时截到末尾，suffix 超过对象大小时取完整长度；起点 ≥ total 等不可满足范围返回 416 并携带 `bytes */total`。对于不支持的多段或非法 Range 可选择忽略并完整 200，但策略冷/热一致。
7. 所有解析都限制安全整数/合理范围；巨大的终点在解析路径中统一处理，避免把完整响应误标成短段并污染缓存。

完整缓存自动截 Range 仍需应用正确处理 If-Range；Cache API 没有保证替你处理所有 HTTP 条件和优先级。先验证前置条件再构造缓存匹配请求。

## 预览与原片

- 站内播放可使用平台生成的压缩预览，下载保留原片；预览状态/引用明确，生成失败不显示不可用链接。
- 根据媒体实际用途降低比特率/尺寸、放置 MP4 元数据以支持快速开始；保持播放、seek、音画、画幅和字幕合同。浏览器播放器统一控制，避免多个实例重复下载/播放。
- 图片提供合理尺寸与版本；未进入视口视频按用户交互/可见性加载，不默认一屏所有卡片都拉原片。
- 预览生成/转码属于可能收费的后台任务，不默认为授权上传或启动生产任务。

## 桶地区与迁移

创建时 location hint 是 best-effort；默认位置与创建请求来源有关。已有桶没有本 SOP 可执行的原地搬迁命令，删除再建同名桶也不能据此迁区。jurisdiction 是法律边界，不能为速度绕开。

优先减少 head/get 往返与不可变字节缓存；多桶同步或迁区增加回源、读写路由、版本一致性和成本，需要设计并批准。R2 全球边缘可访问不等于每 POP 都存完整桶。

## 验收矩阵

- 普通冷 GET/head 调用次数，热 GET/Range 不读 R2；缓存失败仍返回正确文件。
- GET/HEAD、304、412、If-Range 旧/弱/未来值、合法越界416、suffix/open/非法/多段/超安全整数。
- 冷/热摘要一致、seek 可解码、正文长度与 Content-Range 正确、分段缓存不误命中整片。
- 匿名、其他用户/租户、已撤下对象在热缓存时仍拒绝；对本地已缓存副本的撤销窗口明确记录。
- 本地真实 workerd 验证 Cache API 自动 Range 和协议行为；Node fake cache 不证明平台功能。
- 同地区同版本冷热样本分开记录；省 R2 调用可证实，但不直接等价于网页 LCP 或用户全链路收益。
